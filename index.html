Phone Finder India — सिस्टम आर्किटेक्चर

Phone Finder India भारतीय उपयोगकर्ताओं के लिए एक सुरक्षित इंफ्रास्ट्रक्चर पर काम करता है जो वेब क्लाइंट, Google Cloud गेटवे, FCM पुश ब्रोकर और Android डिवाइस को जोड़ता है।

  • वेब क्लाइंट कंसोल: Leaflet.js पर बना मानचित्र इंटरफेस।
  • Google Identity API: OAuth 2.0 + CAPTCHA + MFA प्रमाणीकरण।
  • Phone Finder Core Gateway: REST/WebSockets से कमांड रिले।
  • Firebase Cloud Messaging: Jio/Airtel/Vi/BSNL नेटवर्क पर पुश नोटिफिकेशन।
  • Google Play Services: GPS, Bluetooth बीकन और हार्डवेयर एक्सेस।

कमांड और टेलीमेट्री अनुक्रम

यहाँ समझाया गया है कि प्रत्येक रिमोट कमांड कैसे काम करती है।

1. अलार्म बजाएं (Ring Flow):

  • वेब क्लाइंट POST /devices/{id}/ring भेजता है।
  • Gateway टोकन सत्यापित करता है और FCM को ट्रिगर करता है।
  • FCM Jio/Airtel/Vi नेटवर्क के ज़रिए साइलेंट पुश भेजता है।
  • Google Play Services अधिकतम वॉल्यूम पर अलार्म बजाता है।

2. ऑफलाइन Bluetooth ट्रैकिंग (Phone Finder Network):

  • खोया डिवाइस एन्क्रिप्टेड BLE बीकन प्रसारित करता है।
  • पास का Android डिवाइस बीकन पकड़ता है, GPS लोकेशन जोड़ता है।
  • रिपोर्ट owner की public key से एन्क्रिप्ट होकर Google को जाती है।
  • Owner डैशबोर्ड पर private key से डिक्रिप्ट करता है।

डेटाबेस स्कीमा डिज़ाइन

PostgreSQL डेटाबेस में PostGIS एक्सटेंशन के साथ भारतीय उपयोगकर्ताओं और डिवाइस की जानकारी संग्रहीत होती है।

  • users: Google OAuth ID, ईमेल, मोबाइल (+91 नंबर)।
  • devices: IMEI, मॉडल, Jio/Airtel नेटवर्क टोकन, बैटरी, लॉक स्थिति।
  • location_logs: GPS/Cellular/BLE लोकेशन टाइम-सीरीज़।
  • command_audit_logs: ECDSA-हस्ताक्षरित कमांड ऑडिट ट्रेल।
-- Phone Finder India — PostgreSQL Schema

CREATE TABLE users (
    user_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    google_sub_id  VARCHAR(255) UNIQUE NOT NULL,
    email          VARCHAR(255) NOT NULL,
    full_name      VARCHAR(100) NOT NULL,
    mobile_in      VARCHAR(15),  -- +91 XXXXX XXXXX
    state_india    VARCHAR(50),  -- महाराष्ट्र, दिल्ली, कर्नाटक...
    created_at     TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE devices (
    device_id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    owner_id     UUID REFERENCES users ON DELETE CASCADE,
    fcm_token    VARCHAR(255) UNIQUE NOT NULL,
    imei         VARCHAR(20),
    model_name   VARCHAR(100) NOT NULL,
    network      VARCHAR(30) DEFAULT 'Jio', -- Jio/Airtel/Vi/BSNL
    os_version   VARCHAR(30) DEFAULT 'Android 14',
    battery_pct  INT CHECK (battery_pct BETWEEN 0 AND 100),
    is_locked    BOOLEAN DEFAULT FALSE,
    lock_message TEXT,
    lock_phone   VARCHAR(20),
    is_erased    BOOLEAN DEFAULT FALSE,
    updated_at   TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE location_logs (
    log_id       BIGSERIAL PRIMARY KEY,
    device_id    UUID REFERENCES devices ON DELETE CASCADE,
    location     POINT NOT NULL,       -- (lat, lng)
    accuracy_m   FLOAT NOT NULL,
    source       VARCHAR(30) DEFAULT 'GPS', -- GPS/Cellular/WiFi/BLE
    city         VARCHAR(60),           -- मुंबई, दिल्ली, बेंगलुरु...
    captured_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_device_loc ON location_logs(device_id, captured_at DESC);

CREATE TABLE command_audit_logs (
    audit_id    BIGSERIAL PRIMARY KEY,
    user_id     UUID REFERENCES users,
    device_id   UUID REFERENCES devices,
    command     VARCHAR(30) NOT NULL, -- RING/LOCK/ERASE/SCAN
    signature   BYTEA NOT NULL,
    status      VARCHAR(20) DEFAULT 'QUEUED',
    ist_time    TIMESTAMPTZ DEFAULT (NOW() AT TIME ZONE 'Asia/Kolkata')
);

गोपनीयता और एन्क्रिप्शन प्रोटोकॉल

Phone Finder India एक End-to-End Encrypted (E2EE) नेटवर्क पर काम करता है। Google भी लोकेशन नहीं पढ़ सकता।

1. CAPTCHA सुरक्षा

लॉगिन पर bot-प्रतिरोधी CAPTCHA सत्यापन अनिवार्य है।

2. असिमेट्रिक की-पेयर

Owner की private key Android Keystore/StrongBox में सुरक्षित है। Public key हैश BLE बीकन में प्रसारित होते हैं।

3. क्राउड-सोर्स रिलेइंग

पास का डिवाइस बीकन पकड़कर GPS जोड़ता है और AES-GCM + ECDH से एन्क्रिप्ट कर Google को भेजता है।

4. Zero-Knowledge Storage

Google केवल mailbox का काम करता है। केवल owner client-side पर private key से डिक्रिप्ट करता है।
